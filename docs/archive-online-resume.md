# 存档联网与恢复聊天（2.0.10）


## 2.0.13：不中断的阶段恢复与工作主线

存档整理和提问遇到空正文、截断、非 JSON 整理结果或未形成问题的回复时，自动重试当前模型调用一次；HTTP 408、429、5xx 和网络中断同样最多重试一次。认证/配置类错误不自动重试。每次仍有 150 秒超时，所以故障时整轮可能更慢、产生额外 token 费用；不会无限循环。提问的自动重试不重跑已经完成的搜索/网页读取，外部参考及原话仍保留。持续失败时页面明确提示点击“恢复上次聊天”。

新增持久化字段 `InterviewStage` 记录等待整理或等待提问。整理成功但提问失败时，重启/恢复只继续提问，不重复整理原话。旧存档缺少字段时，沿用先整理最后回答的兼容路径。已有待回答问题继续保留。恢复提问仍可能按当时联网设置重新查证资料。

新增 `InterviewGoal` 保存稳定工作主线，模型更新当前小话题不会覆盖该主线；手动“聚焦这个主题”可切换主线。提问先补任务目标、输入、主要阶段、验收标准、交付物及协作，再深入影响结果的关键决策。根据相关流程草稿缺失字段安排下一问；每累计三条提问，在下一轮注入主线回顾要求，同一局部最多连续追问两轮（用户主动要求深入或关键阻塞除外）。这些是模型选题约束，不是对问句语义的绝对保证。若仍偏题，点击“回到工作主线”可跳过当前细节并重新选题，无需清空存档。

验证：16 项新增检查覆盖空正文恢复、非问题回复、结构格式修复、临时 HTTP 错误、认证失败、重试上限、不重复联网、阶段持久化、重启只续提问、主线防漂移和主线按钮；`test.ps1 -Render` 全部通过。2026-11-10 隔离合成访谈中，模型先整理代码检查→profiling→基准测试流程，转而询问验收标准与谁确定需求底线；设计交付场景转向评审与交付条件。测试未写入真实访谈。原始记录位于开发目录 `artifacts/interview-recovery/live-test.txt`。

## 2.0.12：深度思考

存档整理和追问默认开启高强度思考（`thinking.type=enabled`、`reasoning_effort=high`），无需另开设置。包含回答整理、恢复后的重新整理、格式异常时的补充提取、联网或不联网的追问。仅决定是否搜索及搜索什么的规划步骤仍保持不思考的快速模式。参数依据 [DeepSeek 思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。

整理调用预算为 16,384 tokens，追问为 8,192 tokens，每次超时 150 秒；这些是上限，不要求用满。思考会增加 token 消耗，但简单问题仍可能很快完成。普通聊天继续沿用原有低强度思考配置。

输出截断时不更新知识条目或追加半截问题，保留原话供重试。整理 JSON 的解析上限提高到 24,000 字符，避免套用普通聊天 4,000 字符的显示上限后损坏 JSON。程序仅记录是否有思考结果与服务返回的思考 token 数，不保存或显示思考正文。

验证：新增 15 项检查（7 项访谈调用参数及截断保护、8 项请求序列化与响应处理），完整 `test.ps1 -Render` 通过。2026-11-10 合成访谈真实调用中，整理返回 729 个思考 tokens，耗时约 8.4 秒；追问返回 124 个思考 tokens，耗时约 2.0 秒，两者均完整结束。首个试跑曾收到 HTTP 200 但空正文，按失败处理，重试成功；因此不保证每次 API 请求都成功。测试未改动真实访谈或知识条目。

在「设置 → AI 对话」开启在线 AI、配置 API Key，并开启联网。存档单元的「深入访谈」页会显示联网状态，和普通聊天共用开关。

回答后先由整理器依据用户原话更新知识边界、案例和流程，再判断下一次追问是否需要公开技术资料。需要时最多进行一次搜索和两次网页读取，优先请求原始论文、官方文档与作者仓库；普通工作经历不必每轮联网。实际搜索排名由供应商决定，不能保证每个来源都是一手资料。

本轮问题下的「查证状态与来源」展示实际获取的链接；来源及可读正文节选写入资料库的代码仓、论文或文档分类。缓存不是完整仓库，也不保证拿到论文全文。网页正文只提供给提问阶段，不输入个人能力整理器，不自动升级掌握状态或确认流程。模型整理仍可能出错，应在知识边界和流程页审阅。

联网计划、搜索、网页读取和追问会产生额外 API 请求。规划阶段沿用模型提供商，发送最近访谈来判断查证需求；搜索阶段要求生成仅含公开技术名词的查询，程序拦截明显的密钥、邮件、URL 和本地路径形式，但这不是对所有隐私文本的自动识别保证。敏感访谈可以在设置中关闭联网。资料内容当作外部数据，不授予执行权限。

## 接着已有访谈聊

1. 选择原来的存档，点击「恢复上次聊天」。上方会显示当前主题与最近一次回答。
2. 若还有未回答的问题，原问题保持不变，直接回答即可；不会为恢复而重复调用模型。旧问题显示“没有联网查证记录”，回答后按新版流程查证。
3. 若最后一条是回答（例如之前断网或整理失败），先重新整理已经保存的回答，再继续同一话题；失败时保留原话，恢复按钮可以重试。
4. 暂停后恢复会解除暂停；不会因为历史中的“先暂停”再次自动暂停。浮动输入框的存档菜单也有恢复入口。

数据位置仍为 `%LOCALAPPDATA%\ElymsDesktopPet\archives\archives.json`，不需要新建存档或手工转换。新字段保存每个问题的查证状态和来源，旧记录缺少此字段时按未查证展示。新版本保留最近 1,000 条访谈消息；旧版已裁掉的历史无法由程序还原。
