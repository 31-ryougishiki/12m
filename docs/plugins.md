# 官方插件（第一版）

## 规划与边界

核心保留桌宠、陪伴对话、圆盘、专注、便签、记忆、联网和设置。首批可选插件是存档单元、知识图谱、B站、DSH、云同步。

本版已实现独立页面程序集、安装记录、完整性校验、按需加载、安装/修复/启用/停用/卸载，以及服务入口和后台任务的可用性检查。数据模型、持久化、AI 请求与共享领域服务仍由宿主提供；插件通过宿主契约访问，图谱不依赖存档页面插件，云同步也可独立打开。当前仅支持随应用发布的官方包，不支持任意第三方 DLL，不提供权限沙箱。

后续阶段：抽离各插件专属服务；形成版本化的最小宿主接口；搭建签名发行与下载服务后再提供在线插件目录。第三方插件和进程隔离另行设计，不以文件校验替代安全隔离。

## 使用

圆盘空白扇区「＋」 → 插件页 → 安装 → 重启曳尔沐并应用。圆盘入口的添加与移除也集中在此页，始终保留一个＋空位。

新用户默认不安装任何可选插件；已有用户首次升级也保留所有数据，按需安装功能后继续使用。安装包随 `dist/plugin-packages` 提供，安装不需要联网。发布或移动应用时须保留整个 dist 目录。

隐藏入口仅改变圆盘显示；停用保留插件文件；卸载在重启后删除安装代码，始终保留工作流程、图谱、账号和连接配置。重装会继续使用现有数据。自动云同步、图谱编辑请求监听、B站浏览及 DSH 委托都受插件状态约束。更改待重启期间，旧运行状态保持有效；存在任务时不允许从管理页更改或重启。

功能包加载失败会显示修复入口，核心界面继续可用。插件 UI 延迟到进入对应页面时创建。

## 构建与文件

使用 `build.ps1`，或通过项目的构建后目标调用同一构建流程。`test.ps1 -Render` 同时验证安装生命周期、服务入口和实际页面渲染。

- `plugins/<id>/`：独立功能页面与 `IOfficialPlugin` 入口。
- `src/Plugins.cs`：共享契约、固定官方目录、注册表和安装器。
- `src/PluginPanel.cs`：插件管理和重启入口。
- `dist/plugin-packages/<id>/module.dll`：本版本官方安装源。
- 主程序嵌入 `official-plugins.json`：ID、版本、API 版本、SHA256。
- `%LOCALAPPDATA%/ElymsDesktopPet/plugins/installed.json`：下次启动的安装与启用状态。
- `plugins/installed/<id>/<sha256>/module.dll`：安装代码；版本分目录，避免覆盖已经加载的程序集。

安装先校验官方包、写入并复核文件，再原子保存注册表。保存失败不会启用新包。启动再次核对兼容性与哈希；升级主程序后发现旧包不匹配时，提示更新/修复，不加载旧版代码。卸载后的残留只清理已知插件目录下的固定代码文件，不递归删除用户目录。数据沿用原位置，不迁移、不清空。

本机校验保证包与当前宿主发布内容一致，不承诺抵御已能替换宿主程序的攻击者。安装插件不替代 DSH、B站、云同步等原有执行或账号授权。
