# v1.1 验证记录

环境：本机 Windows，.NET Framework 4.8 WPF，2560×1440 单显示器；2026-11-09。接口测试使用用户提供的 DeepSeek 密钥，密钥只保存在本机设置文件，记录中只显示后四位。

## 自动检查

`ElymsPet.exe --self-test` 通过 27 项，结果见 `tests/results.txt`。原有 15 项全部保留：计时启动、暂停剩余时间、恢复截止时间、提前不结算、到期结算、重复调用不多次结算、休息不计专注次数、时长上限、取消、存档写入、中文与设置往返、损坏主文件恢复备份、异常数据归一化、Y 身份对白、内嵌九姿态图片。

新增 12 项：

- Base URL 归一化与校验（拒绝非 http/https、拒绝带空格 / 查询串的地址）；
- 密钥掩码不泄露中间字符；
- 角色系统提示包含“不是小 Y 长大的样子”“不能真的操作电脑”，且不包含密钥；

- API 错误 JSON 解析（含 `code` 字段，未知字段不导致失败）；
- 空回复保护；
- 16 条上下文上限与清空；
- 设置文件密钥优先；
- `api-key.txt` 回退（临时清空环境变量后验证）；
- 旧版设置缺少 AI 字段时补齐 `Schema`、`AiChat`、接口和模型默认值。

测试使用独立临时存档，不访问网络，结束后删除。

## 真实接口

- `--api-test`：PASS。`deepseek-flash`，`https://api.deepseek.com`，0.60—0.85 秒，`23+1` tokens，回复“接通”。
- `--chat "介绍一下你自己吧，顺便说说你和 Y 是什么关系"`：PASS，1.04 秒，`352+54` tokens。回复明确区分“借着小 Y 的形象”和“不是 Y 长大的样子”，符合系统提示的身份边界。
- 思考模式：临时把 `AiThinking` 设为 true，`--chat` 1.92 秒、`373+141` tokens，回复正常，确认 `thinking` 与 `reasoning_effort` 序列化可用；随后恢复为非思考模式。
- 错误密钥：把本机设置临时换成 `sk-invalid-...`，`--api-test` 返回 HTTP 401、退出码 1，界面提示“密钥没有通过验证，请在「设置」里检查 API Key。”，详情含服务端 `Authentication Fails`；恢复真实密钥后重新 PASS。
- 余额：`GET /user/balance` 返回 `is_available: true`、466.72 CNY，与接口可用状态一致。

## 真实窗口

启动 `ElymsPet.exe --panel`，用 Windows UI Automation 与真实鼠标事件操作：

- 陪伴页显示“● 已接入 DeepSeek V4.1 Flash · 密钥保存在本机”；设置页显示“当前密钥：sk-…023e（来源：设置文件）”，没有显示完整密钥。
- 输入“这次用回车发送：我们之间靠什么保持联络？”后按 Enter 发送成功；1.1 秒收到 46 tokens 的回复，内容为“靠这条桌面上的信号线呀……”。气泡同步显示，面板记录追加“你 / 曳尔沐”两行。
- 修正前第一次 Enter 测试没有发送：`TextBox` 设置了 `AcceptsReturn=true` 后，Enter 被控件类处理，实例的 `KeyDown` 收不到；改为 `PreviewKeyDown` 后在真实窗口中重测通过。
- “测试连接”返回“● 连接正常 · deepseek-flash · 0.6s · 回复：接通”。第一次点击后截图没有变化，是因为结果提示位于滚动区下方；滚动后确认成功，不是接口失败。
- 设置页的密钥输入框为空时不会覆盖已保存密钥；“保存 AI 设置”、接口地址、模型、深度思考、清空对话记忆均有对应控件。
- 真实窗口截图：`preview/ai-chat.png`（面板对话）、`preview/ai-pet.png`（桌宠气泡）、`preview/ai-settings.png`（测试连接结果）。
- 各标签页和桌宠执行 WPF 渲染预览（`preview/`），检查文本、控件和滚动布局；首版聊天卡片过高导致输入框被推到首屏外，已压缩聊天记录高度并把发送按钮放到输入框右侧，重新渲染确认可见。

## 未完整实测的边界

- 中文输入法候选词阶段的 Enter 行为没有用真实 IME 逐项测试；本轮用剪贴板输入中文。代码避开了 `Key.ImeProcessed` 分支，但不能保证所有输入法一致。
- HTTP 402（余额不足）、429（限流）、5xx 和网络超时没有真实制造，只通过错误映射与自检覆盖；401 已真实测试。
- 16 条上下文之外的长期对话、请求进行中关闭并重开面板、多个面板并发没有逐项测试。
- 不同 DPI 的多屏切换、所有独占全屏游戏、热键与第三方软件的全部冲突组合；拖拽和托盘在当前代码中实现，但本轮没有完成覆盖所有分支的人工操作测试。
- 没有实现流式输出、图片 / 视觉识屏、工具调用、语音合成；不声称具备这些能力。
- 换一台没有密钥的电脑后，需要在设置页重新粘贴密钥；本轮只在本机验证了设置页与 `--set-key` 写入，没有做第二台机器的完整流程。
