# 流程逐项补充

存档单元保留深入访谈、流程、知识图谱和云同步四页。知识边界、资料库、案例复盘不再作为独立页面；历史知识、来源、案例和云端版本仍保留。存档管理、访谈记录、云连接设置默认折叠。

## 使用

1. 在深入访谈填写大概流程名，例如「把模型拉起来跑测试」，点击「匹配流程，逐项补充」。精确名称直接匹配，模糊名称交给已配置的 AI 判断；多个候选时选择其中一个，没有匹配时不会新建流程。
2. 曳尔沐依次展示适用场景、前置条件、操作步骤、验收与测试、异常处理的现有内容，并询问需要补充或纠正的地方。编号步骤逐项询问，未编号的步骤文本作为一个单元；代码块里的编号不会被拆散。
3. 输入补充，点击「保存补充并继续」。没有补充则跳到下一项。AI 只整理当前单元，保存成功后前进；任何内容发生修改，流程回到草稿状态，最后在流程页审阅确认。

流程页每套流程也有「逐项补充」按钮，无需输入名称。还没有流程时，在深入访谈填写主题，点击「聊新主题」描述操作步骤，生成流程草稿后再补充。

## 保存与恢复

回答先保存在本机，再请求 AI 整理。断网或输出不完整时停留在当前单元，点击「继续 / 重试」；重启后仍保留流程、进度和待整理回答。云端快照也包含这些状态。结束本轮会停止逐项询问，已经保存的修改和访谈原话保留。

如果流程在补充期间被其他操作修改，停止应用旧结果，保留原话；结束本轮并重新选择流程。超过字段长度限制时保留原内容，不截断命令。补充流程记录不会执行模型部署或测试命令。

## 验证

`WorkflowReviewTests` 覆盖候选校验、代码块保留、逐步骤写回、失败重试、重启续接、确认状态、云端序列化、外部修改冲突和长度限制。真实模型另用独立临时示例验证模糊名称匹配及只修改当前步骤，没有改动用户已有流程。
